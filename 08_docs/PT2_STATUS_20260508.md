# PortaTreasure2 Project Status

_Last updated: 2026-05-08_

## 1. Project purpose

PortaTreasure2 is an R-generated, standalone Leaflet HTML webmap intended to function as a fast hydrologic screening portal for California and broader western water-resources work. The map is designed to reduce repeated VPN, ArcGIS, and manual web-portal checks by putting curated water-resource, land-status, basin, gage, groundwater, conveyance, water-right, snow/soil, operational-weather, and reference layers into one shareable browser-based tool.

The current product is no longer just a prototype. It is a working, modular webmap framework with preprocessing, cache-building, label-building, and final HTML-generation stages. It supports a large number of hydrologic and reference layers, custom Leaflet controls, HUC precipitation/recharge theming, map notes, live operational overlays, labels, popups, hovers, and performance-aware clustering.

## 2. Current architecture

The project uses a staged R workflow:

```text
raw source files
  -> preprocessing scripts
  -> processed RDS/GPKG/QA outputs
  -> map-ready core cache
  -> optional label cache
  -> final standalone HTML
```

The major design principle is to keep heavy spatial processing out of the final HTML builder. The final map script should read already-prepared cached layers, add them to Leaflet, add controls, and write the HTML. It should not download raw data, parse source files, compute spatial intersections, build complex popups from scratch, or perform heavy geometry operations.

## 3. Common build commands

Run these from the PortaTreasure2 project root.

### Load the runner

```r
source("run_build_map.r")
```

### Fast rebuild after UI-only or final-map-only changes

Use this when changing Leaflet drawing helpers, UI controls, map notes, HUC dropdown JavaScript, or final HTML behavior without changing cached fields.

```r
build_final_map_only()
```

### Rebuild map-ready cache and final HTML

Use this when changing cache fields, popup text, hover text, symbology fields, joined attributes, or anything in the core cache blocks.

```r
rebuild_core_cache_and_map()
```

### Rebuild labels and final HTML

Use this when changing label fields, label include settings, label zoom thresholds, or label helper behavior.

```r
rebuild_label_cache_and_map()
```

### Rebuild core cache, labels, and final HTML

Use only when both map-cache and label-cache outputs need to change.

```r
rebuild_everything_from_cache_and_map()
```

### Current important custom runner workflows

```r
refresh_new_static_water_layers_and_map()
refresh_calsim3_arcs_and_map()
refresh_huc_gw_county_and_map()
refresh_usgs_and_map()
refresh_cnrfc_points_and_map()
```

The current `refresh_calsim3_arcs_and_map()` workflow now effectively refreshes both CalSim3 arcs and CalSim3 nodes because the CalSim3 preprocessor has been expanded to handle both.

## 5. Current layer inventory and functionality

### Core / BLM / administrative context

- BLM-CA Managed core lands.
- BLM held/managed differences.
- BLM offices.
- BLM field-office outer boundaries.
- Counties.
- Project areas placeholder layer, currently empty in the latest build.

### Basins and hydrologic units

- HUC2, HUC4, HUC6, HUC8, HUC10, HUC12.
- Bulletin 118 groundwater basins.
- CNRFC basins.
- CNRFC FNF Delta basins.
- Groundwater Sustainability Plan Areas and other manifest-driven reference basin layers where included.

### HUC climate/recharge theming

A custom HUC dropdown is one of the most important map controls. It allows each HUC layer to be filled using five choices:

```text
No fill / boundaries only
PRISM precipitation, inches/year
PRISM precipitation volume, kaf/year
BCMv8 recharge, inches/year
BCMv8 recharge volume, kaf/year
```

The HUC fill data are precomputed in the cache and applied in-browser to existing HUC polygons. This avoids duplicating HUC geometries for every metric. The HUC theme JSON serialization was recently revised to avoid the jsonlite named-vector warning by passing explicit record lists and reconstructing lookup objects in JavaScript.

### Points and gages

- CNRFC stream gages.
- CNRFC precipitation gages.
- USGS streamgages.
- USGS groundwater wells.
- Springs.
- SCAN stations.
- Snow pillows.
- SWRCB / CalWATRS PODs/WRs relevant to BLM.
- CVP/SWP X2 kilometer reference points.
- CalSim3 nodes.

### Water rights / PODs

The SWRCB / CalWATRS POD layer has been enhanced using a SWRCB-provided 2026 BLM water-right CSV:

```text
01_raw_data/swrcb_water_rights/All_your_water_right_7_1_2026_8_56_30.csv
```

The CSV is used as a lean water-right ID lookup only. The relevant unique field is:

```text
Water Right/Claim ID
```

The joined map layer includes a compact popup row:

```text
SWRCB 2026 BLM WR list: Yes/No
```

The former separate green ring layer was replaced with conditional styling on the main POD markers. PODs whose water-right/claim ID appears in the 2026 SWRCB-provided BLM list are drawn with a bright-green marker outline and slightly emphasized marker styling. This integrates the indicator into the normal POD clustering/declustering behavior and avoids a separate unclustered ring overlay.

The TOC layer is now named:

```text
Points – SWRCB PODs/WRs relevant to BLM [1]
```

Map note `[1]` should explain that the green marker outline is a screening flag, not a legal determination of ownership, assignment, POD accuracy, or current status.

### Conveyance / channels

- Major Conveyance.
- Deltamapr Conveyance.
- CalSim3 arcs.

Major Conveyance operator grouping was refined so non-CVP/SWP features are identified as:

```text

```

Deltamapr Conveyance uses operator text to style lines:

```text
Central Valley Project / USBR / Bureau of Reclamation / Reclamation = CVP color
State Water Project / DWR / Department of Water Resources = SWP color
Other = neutral
```

The true `Operator` value is preserved in hover and popup text.

### Water districts

Source:

```text
01_raw_data/water_districts/i03_WaterDistricts.shp
```

Main field:

```text
AGENCYNAME
```

The water district polygon layer is intentionally a light reference layer with very faint fill and colored outlines. Because many water district polygons overlap or contain smaller “island” districts, full hover/click access is not always reliable. The practical workaround is a separate label layer:

```text
Labels – Water Districts
```

Water district labels use point-on-surface label points, are clustered/invisible until close zoom, and are intended to help identify districts when polygon popups are inaccessible due to overlap.

### Reference layers

Manifest-driven reference layers are read through:

```text
00_config/reference_layers_manifest.csv
```

Reference layers are cached as a named list in:

```text
04_processed_data/cache/latest/reference_layers_all_map.rds
```

Some reference-layer popups still need normalization. This remains a major future improvement area.

### Live operational overlays

The Ops panel is separate from the main TOC and starts collapsed by default. It includes live operational overlays such as radar/QPE/QPF/ERO-style layers. These are intentionally separate from the main Leaflet layer control and are fetched by the browser when available.

## 6. Important UI controls

### Main TOC

The main TOC is built as a standard Leaflet layer control and then enhanced with custom JavaScript in:

```text
03_functions/leaflet_core_helpers.r
```

The helper adds:

```text
collapsible Layers header
Basemaps header
Core / Basins / Points / Channels / Reference / Labels headers
short display names by stripping category prefixes
sticky top title ribbon
one internal scrollbar
```

A recent UI fix pre-hides the raw, ungrouped Leaflet TOC until the custom headers are applied, preventing users from briefly seeing the old ungrouped layer list during page load.

### Map Notes button

The map notes button is implemented in:

```text
05_map_build/04_build_portatreasure2_core_map.r
```

This block is fragile because it is large JavaScript/HTML embedded inside an R string. A previous issue occurred when an apostrophe in `POD's` broke the JavaScript string and caused both the Notes button and the HUC dropdown to disappear. The wording was changed to avoid the apostrophe:

```text
the POD water-right/claim ID appears...
```

Caution: avoid unescaped apostrophes in JavaScript HTML string fragments inside this file.

### HUC fill dropdown

The HUC dropdown is also implemented in:

```text
05_map_build/04_build_portatreasure2_core_map.r
```

Because it initializes after earlier custom JavaScript controls, a syntax error in an earlier `onRender()` block can prevent it from appearing. If the dropdown disappears, immediately check the browser console for JavaScript errors.

### Ops panel

The Ops panel is implemented in:

```text
03_functions/leaflet_ops_live_helpers.r
```

It now starts collapsed to reduce initial visual clutter.

### Mouse coordinates

Mouse coordinate readout is implemented in:

```text
03_functions/leaflet_core_helpers.r
```

## 7. Smoke-test checklist after any replacement script

After any script replacement that touches final-map JavaScript, run:

```r
source("run_build_map.r")
build_final_map_only()
```

Then open the newest HTML and check:

```text
1. Browser console has no red JavaScript syntax errors.
2. Main TOC appears with headers and no raw TOC flash.
3. Main TOC collapses/expands.
4. Ops panel starts collapsed and expands.
5. Notes button appears and opens the notes overlay.
6. HUC fill dropdown appears.
7. HUC fill choices work:
   - No fill
   - precip in/yr
   - precip kaf/yr
   - recharge in/yr
   - recharge kaf/yr
8. SWRCB PODs/WRs layer toggles and clusters.
9. SWRCB 2026 BLM WR flag appears as marker outline, not as a separate unclustered ring layer.
10. CalSim3 nodes draw and popups show CalSim3_ID, Riv_Name, Comment, NodeDescri, and documentation link.
11. Water District labels draw only at the intended zoom threshold.
12. USGS wells still perform acceptably when toggled.
```

If Notes and the HUC dropdown are both missing, suspect an earlier JavaScript syntax error in `04_build_portatreasure2_core_map.r`.

Labels should be added carefully because of file size and performance.

Current label system is solid:


Recommended label tiers:

```text
Tier 1:
  high value, low/medium feature count

Tier 2:
  useful but potentially cluttered

Tier 3:
```

Water District labels are a successful example of using labels as a practical workaround for overlapping polygon click/hover limitations.

### 9.6 Live observation refresh with cached fallback

Longer-term ambition: allow the standalone HTML to use cached values by default, but attempt live data fetches where browser/security conditions allow.

Design pattern:

```text
Default:
  show cached values from the last R preprocessor run

Optional:
  user clicks “try live refresh”
  browser fetches latest values from USGS/CDEC/NRCS/etc.
  map updates if fetch succeeds

Fallback:
  if browser or agency computer blocks fetch, retain cached values and show a clear status message
```

Recommended first pilot:

```text

```

CDEC, SNOTEL, SCAN, and other live sources should come later after the USGS design is stable.

Avoid building two entirely separate HTML versions at first. Prefer one HTML with graceful fallback.

## 10. File-size and performance notes

Current output size is about:

```text
209 MB
```

This is large but still functioning.

Big contributors likely include:

```text
self-contained HTML dependencies
large point layers
USGS wells
labels
HUC geometries and popup strings
water districts
reference layers
```

Performance principles:

```text
Cluster large point layers.
Avoid always-visible labels for dense layers.
Use label zoom thresholds.
Avoid duplicating large geometries for thematic variants.
Use cached styling fields instead of repeated JS computation where helpful.
Keep raw/source fields slim before caching.
Prefer short popups where possible.
Use non-interactive visual elements when they are only decorative.
```

Potential future performance work:

```text
USGS wells split into all vs active/recent
optional non-self-contained HTML for internal fast loading
reduce popup verbosity for very large layers
aggressively slim cache fields
move repeated popup text into shared JS where possible
review label cache size
```

## 11. Development rules / lessons learned

### Preserve working final-map JavaScript

The map now depends on several custom JS controls. Replacing `04_build_portatreasure2_core_map.r` from an older version is risky. Before any replacement, verify that the version includes:

```text
Notes button
HUC 5-choice fill dropdown
SWRCB 2026 note wording without fragile apostrophes
HUC JSON-safe theme data
CalSim3 nodes
current layer list
```

### Prefer latest-file replacements

Because this project is moving quickly, ask for the latest current file before generating whole-script replacements. This is especially important for:

```text
04_build_portatreasure2_core_map.r
leaflet_layer_helpers.r
leaflet_core_helpers.r
04_cache_admin_water_reference_layers.r
02_build_core_map_cache.r
config_source_files.r
config_map_display.r
popup_helpers.r
```

### Keep core cache and final HTML responsibilities separate

Do not put heavy data processing into the final HTML builder. Keep this distinction:

```text
Preprocessor:
  raw source -> clean processed RDS

Core cache:
  processed RDS -> simplified, popup-enriched, styled map cache

Label cache:
  map cache -> label point layers

Final map:
  cache -> Leaflet HTML
```

### Avoid duplicate group-name mismatches

If a layer does not toggle, check that the group name is consistent in:

```text
pt_layer_group_name()
CORE_OVERLAY_GROUPS
the add*() Leaflet function group argument
```

### Treat map notes as production documentation

Map notes are part of the user-facing documentation. They should be kept concise, cautious, and screening-oriented.

### Use cautious wording

For screening layers and interpreted flags, avoid legal-sounding conclusions. Prefer phrases like:

```text
appears in
screening flag
provided list
relevant to BLM
not a legal determination
```
